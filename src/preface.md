# 前言

> 本章导览：为什么写这本书、写给谁、如何使用配套代码。

## 为什么写这本书

2025 年之后，"AI 写代码"不再新鲜，新鲜的是**谁来指挥 AI 写代码**。Coding Agent——能读代码库、改文件、跑测试、自主多步工作的程序——正在成为程序员的日常工具。用它们的人很多，但理解它们怎么造出来的人很少。

这中间有一道奇怪的鸿沟：Agent 开发没有任何黑魔法，它不需要你懂机器学习，不需要 GPU，甚至不需要太多新概念——本质上是"一个会调用工具的循环"。但如果你只从产品文档和 prompt 技巧入手，很快会撞上一堆没有答案的问题：

- 为什么 Agent 有时改完文件就"忘了"读过什么？
- 上下文满了之后到底发生了什么？会话为什么能"压缩"而不丢失关键约束？
- 工具明明很多，为什么有的并行跑、有的排队？
- 权限弹窗背后的规则引擎长什么样？"Always allow" 到底记到了哪里？
- 子代理和主代理是什么关系？为什么它看不到我之前的对话？

这些问题没有一个能在教程里找到答案，但每一个都写在真实系统的源码里。

本书的做法是：**拿一个真实的生产级 Coding Agent 当标本，一层层解剖给你看**。标本就是 ZCode 的 Agent CLI——一个每天在真实用户手里跑的 TypeScript Coding Agent，约十几万行源码，覆盖了 Agent 开发中几乎所有的工程问题。我们把它的每个机制（工具系统、上下文管理、压缩、记忆、子代理、权限、定时任务……）拆出来，讲清楚它为什么这样设计，然后用最少的代码实现一个教学版，让你能亲手复现。

读完本书，你得到的不是"如何用好某个 AI 编程工具"，而是**构建任何一个 Coding Agent 所需的完整知识体系**——以及一堆可以直接搬去用的设计决策。

## 读者画像与先修知识

本书写给**会编程、但没做过 Agent 的程序员**：

- 你不需要任何机器学习背景。全书只在 1.4 节讲一点 LLM 的原理，且是为工程服务的（token、上下文窗口、缓存），不涉及模型训练与数学。
- 你需要熟练使用至少一门静态类型语言（TypeScript / Java / C# / Go 皆可），读懂函数、接口、异步调用。
- 你需要基本的命令行与 Git 使用经验。
- TypeScript 语法不熟也没关系：本书刻意回避语法细节，所有示例用最平实的写法，见约定章。

## 配套代码与运行方式

本书有两条代码线：

1. **tinycode**：全书从零构建的教学项目。每章给出可誊抄的代码清单，随章节演进为一个完整的 Coding Agent。它只用 Node.js 内置能力与原生 `fetch` 调用任何 OpenAI 兼容 API（包括本地部署的模型），无需付费服务即可完整跑通。
2. **真实源码**：ZCode CLI 的开源仓库。书中以 `packages/core/src/...` 形式的路径指路，建议读者把仓库克隆下来对照阅读——本书每章的"源码对照"部分就是你的阅读地图。

运行 tinycode 只需要 Node.js 20+ 和一个模型 API Key（或本地模型端点），核心阶段快照见 `code/tinycode/`。

## 如何阅读本书

- 第一部分（第 1 章）：用四次递进的代码把"调 LLM API"这件事讲透，是全书的基石。
- 第二部分（2.1–2.6）：Agent Runtime 的核心机制——循环、工具协议、上下文工程、压缩、子代理、持久化。这是全书最重要的部分。
- 第三部分（3.1–3.5）：Coding Agent 特有的工具如何实现：文件读写、代码编辑、搜索、执行、Git。
- 第四部分（4.1–4.4）：扩展机制：Hooks、Skill、Plugin、多模型接入。
- 第五部分（5.1–5.7）：一个个具体的功能范式：Todo、Plan 模式、权限、Goal、定时任务、后台任务、动态工作流。
- 第六部分（6.1–6.4）：怎么观测、评测、加固一个 Agent。
- 第七部分：方法论与展望，不写代码。

时间紧张的读者，最小路径是 **1.2 → 2.1 → 2.3 → 2.4 → 5.3**：这五章讲完了"Agent 为什么是个循环"、"上下文为什么需要经营"、"安全边界为什么长这样"这三件事。

## 排版与勘误反馈

书中引用真实系统源码时，路径相对 `apps/zcode-cli/`；引用教学代码时，路径相对 `code/` 下对应阶段目录。由于真实代码持续演进，若你看到的源码与书中描述有出入，以"机制与设计动机"为准——它们比行号稳定得多。
